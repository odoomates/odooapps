You decide what the AI may call
Outside tools are imported switched on but not read only: the agents ask the user before calling them. You mark the safe ones read only, switch off the others, and limit each server to the groups you choose.
How it works

Three steps

One form per server in AI > Configuration > Outside MCP Servers.

Add the URL
The MCP endpoint of the server, a prefix for its tools, a timeout and extra headers if needed.
Sign in
No authentication, a bearer token, or an OAuth sign-in: Odoo finds the authorization server and registers itself.
Choose the tools
Connect imports the tools with their descriptions and schemas. Switch them on or off, mark them read only.
Ask
The AI Assistant in Discuss and the agents of other modules call the tools for you.

Tools as AI tools

Each tool of the server becomes a tool of the AI Engine, named with the prefix of the server. The server says whether a tool is read only or destructive; Odoo shows it as a hint and lets you decide. Refresh Tools keeps your choices.

In the AI Assistant

Read-only outside tools are available to the AI Assistant in Discuss, next to the built-in tools that look up Odoo records. The answer comes in the chat.

OAuth sign-in, done right

Discovery from the 401 of the server, dynamic client registration or your own client ID, the authorization code flow with PKCE, state and resource indicators. Tokens refresh on their own, with rotation respected across workers, and Sign Out revokes them. Secrets never go back to the browser.

Every tool under control

The tool form shows the server, the name of the tool there and its hints. Its JSON schema comes from the server. Allowed groups of the server apply to all its tools.

What the server says about itself

Connect reads the name, version, protocol version and instructions of the server. Each call is in the AI usage log with the user, the server, the tool, the duration and the result.
Protocol

Speaks Streamable HTTP

The current MCP transport, with the details that make it work with real servers.

JSON or events
Answers as one JSON object or a stream of server-sent events; ping requests of the server are answered.
Resumes streams
A stream that closes before the answer is resumed with Last-Event-ID, after the retry delay of the server.
Sessions
Mcp-Session-Id and MCP-Protocol-Version kept per server; an ended session is opened again by itself.
Results
Text, embedded resources, links and structured content are given to the AI; tool errors come back as errors.
Good to know
  • Needs the free AI Engine (om_ai) of Odoo Mates and an AI provider (your own key or a local model).
  • One set of credentials per server: its tools act with the account that signed in, for every allowed user.
  • Streamable HTTP servers only; tools only (resources and prompts of outside servers are not imported).
  • Works with the free MCP Server module too: connect two Odoo databases, or this one to itself to try it.
