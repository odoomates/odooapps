Part 1

Before you start

1.1 What the app does

User Access Manager groups users into access profiles. On a profile you decide, from the real menus of your database, what its users see and do:

  • which apps and menus they see
  • Read, Create, Edit and Delete on each kind of data
  • which records: their own, their team's, their warehouse's…
  • fields hidden, read-only or required
  • buttons hidden or refused
  • reports and Action menu entries
  • tabs, filters, views, chatter, activities
  • export, import, archive, duplicate
  • working hours, networks, one session per user
  • Point of Sale rules, with the POS add-ons

No code is needed, and the important rules are enforced on the server, not only hidden on the screen. The app is completely free and open source (LGPL-3).

1.3 Installing

  1. Download the module for your Odoo version and put it, with om_user_audit, in your addons folder.
  2. In Odoo, turn on developer mode, open Apps and click Update Apps List.
  3. Search User Access Manager and click Activate (Install). The audit app installs with it.
  4. For the Point of Sale, install POS Access Control too; the bridge modules install by themselves (part 11).

Try it on a copy first

Access rules touch every screen of Odoo. Build and check your profiles on a copy of your database, then export them and import them on the live one (12.5).

1.4 Who manages the access

The app adds an Access Manager app to the home screen, for the members of the group Access Management / Manager. The Administrator is one of them from the start. To let someone else manage profiles, tick that group on their user form: they need no Settings rights.

The app has three menus: Access Profiles, Why? and Health Check.

1.5 Five rules to keep in mind

  1. No profile, no restriction. A user who is in no profile works as before. Nothing changes until you put someone in a profile.
  2. A profile only takes away (or gives an app, 3.4). The user's own groups still decide what Odoo gives them in the first place.
  3. Administrators are safe. The superuser and the Administrator user are never restricted. A Settings user is only restricted by a profile that ticks Apply to Settings Users.
  4. The last access manager is kept. A change that would leave nobody able to open the Access Manager is refused.
  5. Hidden is not forbidden. A hidden menu is cosmetic; denying Read on the data is what forbids it (14.1).

Your first profile

2.1 Three ways to start

Open Access Manager › Access Profiles. The list has three buttons above it:

Whichever way you start, the result is an ordinary profile. Give it the name of the people it is for, say Warehouse Staff: the name shows on their user form.

2.2 Who carries a profile

WhereWho gets the profile
Users top of the formThe users you add. A user can be in several profiles.
Also Given To Options tabThe members of Odoo groups: they get the profile while they are in the group.

From the users list you can also work on many users at once: select them, then Action › Set Access Profiles (add, remove or replace). On a user form, Copy Access to… copies or moves that user's profiles to another user.

2.3 Additive or Override

When a user is in several profiles, each profile says how it combines with the others (Options tab):

  • Additive (the default): profiles add up, like Odoo groups. The user may do something as soon as one of their additive profiles allows it, and something is hidden only when all of them hide it.
  • Override: always applies, on top of the others, and is never overruled. Use it for a blanket limit such as Read Only Everywhere.

In practice

Adding an additive profile can only give access back, never take it away. If a restriction must hold whatever else the user carries, put it on an Override profile.

2.5 The Setup Wizard, step by step (Odoo 16 to 20)

The Setup Wizard builds a profile by asking questions, one screen at a time. Open it with Setup Wizard above the profiles list for a new profile, or on a profile's form to go through an existing one (on Odoo 16, only on the form). The screenshots are from Odoo 19. The steps are numbered at the top: click one to go back to it.

Nothing applies until Finish

A new profile stays off while you set it up: it applies to its users only once you click Finish. On a profile already in use, each answer applies at once, as on the menu tree.

Step 1 – Who

Name the job, for example Salesperson or Warehouse Team, and add the users who do it. Users can also be added later. The name is used to tick the apps of the job for you in the next step.

Step 2 – Apps

Tick the apps these users work in; every other app is hidden from them. From the name Salesperson, Sales is already ticked. Tick all and Untick all help with long lists. Each app ticked becomes a step of its own.

Step 3 – One step per app

For each app ticked, up to five pages, numbered under the app's name. Next goes through them in order.

PageWhat you decide
1. MenusWhich menus of the app they see, laid out as in the app's top bar. Untick a menu to hide it with the menus under it; untick Configuration for users who only do the daily work.
2. RecordsRead only in this app, or which records they see: all of them, or Limit records of… a data, with the one-click choices of 5.1 (their own, their team's, this month…).
3. ReportsThe Print and Actions menus of each screen, as Odoo shows them: untick what they may not use. Allow all and Hide all per menu.
4. ButtonsThe buttons of each screen, where Odoo shows them. Click a button to hide it; on a hidden button, the lock blocks it too, so the server refuses it.
5. FieldsThe form of each screen: click a field or its label once for Read only, twice for Hidden, three times for Normal again. Click a tab name to hide the tab.

Step 4 – Everywhere

What these users may not do in any app: Block Export, Block Import, Block Archiving, Block Duplication, Hide Costs and Margins, Hide Sales Prices, Block Developer Mode, Read Only Everywhere. All are off by default.

Step 5 – Review

A summary: the users, each app with its access and its record limit, and the apps hidden. Click Preview as User to see Odoo as one of them, then Finish. Everything set here can be changed later, with the Setup Wizard again or on the menu tree (part 3).

On Odoo 15

The Setup Wizard is not there yet. Start from New from Template or an empty profile and use the menu tree: parts 3 to 8 set the same things.

Part 3

Menus and apps

3.1 The menu tree

The Menus & Apps tab, the first one, shows the real menus of your database. Almost everything is set from here:

  • Untick a menu to hide it, with everything below it.
  • Click a menu to set, in the panel beside the tree, what its users may do there: rights, records, fields, buttons, tabs, filters, views, Print and Action menu.

Changes are saved at once and written in the history of the profile. Small marks on a menu show what is restricted there; tick Only what is restricted above the tree to see the whole profile at a glance.

3.2 Hiding a menu or an app

Untick the app (Point of Sale, Invoicing…) or one of its menus (Sales › Configuration). The users no longer see it in their menus.

Hidden is cosmetic

A hidden menu can still be reached by a link or through another menu. To really forbid the data behind it, remove Read on that data (part 4).

3.3 A whole app at once

Click an app or a submenu. The panel offers one-click levels for everything below it:

LevelResult
Full accessNothing restricted (back to normal).
No configurationThe app's Configuration menus are hidden; the rest works as usual.
Read onlyThey see everything in the app and change nothing.
No accessThe app is hidden and its data cannot be read, created, edited or deleted.

A submenu or a data below can still be set differently: the closest setting wins. Data that other apps share (customers, products) is left alone unless you tick Also shared data.

3.4 Giving an app the user does not have

An app that some user of the profile cannot open is shown unticked and marked Not given. Tick it to give them its user level (for example Purchase / User); Access to the app picks another level. The profile then restricts it as usual. The access goes away with the profile. Groups that would make someone an administrator or an access manager are never given this way.

3.5 Restrict an App

The Restrict an App link above the tree opens one app on one screen: its menus, data, reports and Action menu entries, each with a checkbox, ticked for you by the level you choose. Useful when you want to see all of an app at once.

Rights are per data, not per menu

Odoo checks rights on the data. Quotations and Orders both open sales orders, so what you set on Quotations also applies to Orders. The panel tells you which other menus open the same data.

Part 4

Read, Create, Edit and Delete

4.1 Rights per data

Click a menu in the tree. Under Rights, untick what the users may not do: Read, Create, Edit, Delete. The server enforces it, so the Create and Delete buttons leave the screen on their own.

Example: a salesperson may create and edit quotations but not delete them: click Sales › Orders › Quotations and untick Delete.

4.2 Read only, everywhere or in one app

  • One app: click the app and choose the level Read only (3.3).
  • Everything: tick Read Only Everywhere on the Restrictions tab. Put it on an Override profile if the user carries other profiles.

4.3 Edit drafts only

Beside Records, tick Edit drafts only: the users see all the records allowed, but may only change the ones still in draft. More generally, one record filter applies to all four operations, and each operation can be narrowed on its own: that is how you allow editing a few records without hiding the others.

Part 5

Which records they see

5.1 The one-click choices

Click a menu, then open the Records list. Each choice is offered only when the data has what it needs:

ChoiceThey see
All recordsEverything Odoo already lets them see.
Their Own RecordsRecords where they are the salesperson, the responsible…
Their Sales TeamRecords of their sales team.
Their CompaniesRecords of the companies they belong to.
Their WarehouseRecords of their warehouse.
Theirs and their team'sTheir own and their reports' in the org chart, three levels down (with Employees).
Created today / this week / this month / this yearRecent records only.

5.2 A filter of your own

For anything else, click Custom filter… and build it with Odoo's filter editor, for example Customer is in Kuwait or Salesperson is the user. It works like a standard Odoo record rule and can use user, company_id and company_ids, e.g. [('user_id', '=', uid)].

A filter is enforced by the database: records outside it do not exist for the user, in lists, reports, searches and exports alike.

5.3 Allowed records: journals, warehouses, shops

Some data is easier to pick by name: only these journals, points of sale, warehouses, locations, sales teams or dashboards. Allowing a record also filters what belongs to it: allowing two journals filters their entries, journal items and payments too.

  • Pick them on the profile, under Allowed records of the app;
  • or tick Each User's Own, and set them on each user's form (tab Allowed Records). One Cashiers profile then serves every cashier, each on their own point of sale.

Part 6

Fields

6.1 Hidden, read-only, required

Click a menu and open Fields. The form of that menu is shown: click a field (or its label) and choose Hidden, Read-only or Required. Visible brings it back.

A hidden field is blanked in everything the user's browser or a script receives, and searching, sorting, grouping or exporting on it is refused. What is written to a hidden or read-only field is ignored.

6.2 Only when a condition holds

A field, button or tab rule can carry a condition, Only When, written like Odoo's view conditions:

  • state == 'sale' – the customer reference hidden on confirmed orders
  • amount_total > 1000 – the discount locked above an amount
  • amount_total > 1000 and not partner_id

Fields compared with fixed values, uid, and, or and not are supported; anything else is refused when you save the rule.

6.3 Links, dropdowns and exports

Under More settings of a field you can also:

  • remove the link of a relational field (no opening the customer from the order);
  • stop creating records from its dropdown;
  • filter the values it offers (only some payment terms), checked when the record is saved;
  • keep it out of the exports while it stays on the screen.

6.4 Hide costs, hide sales prices

Two switches on the Restrictions tab, valid in every app installed now or later:

  • Hide Costs and Margins: product cost, margins of sales and of the point of sale, stock valuation.
  • Hide Sales Prices: sales prices, discounts and amounts.

Printed documents

Odoo's own code still uses these values (a delivery must be valued). A PDF or email Odoo builds may still show them: hide that report too (7.2).

Part 7

Buttons, reports and actions

7.1 Hide, block, or both

Click a menu and open Buttons: the buttons of its screens are listed, stat buttons and kanban links included. For each one choose:

ModeEffect
VisibleThey see it and can use it.
HiddenNot on the screen, but it could still be run another way.
BlockedNot on the screen, and refused by the server however they try it. This is the safe choice.

A button rule can carry an Only When condition too: Cancel refused once the order is confirmed. In developer mode, Scan Buttons on the Buttons tab reads the buttons out of the views of any data.

7.2 Reports and the Action menu

Under Print and Action Menu of a menu, untick the reports and entries (Send by Email, server actions…) they must not use. They are also refused when reached by their id or URL. To remove every one at once:

  • Hide the Print Menu – no report can be printed;
  • Hide the Action Menu Entries,

both on the Restrictions tab.

8.2 Tabs, filters and views

Click a menu, then:

  • Pages: hide notebook tabs of the form (with a condition if you like);
  • Filters: hide search filters and group-bys, or the search panel;
  • Views: hide whole view types, such as Kanban or Pivot.

8.3 Chatter and activities

  • Hide Send Message: only Log note remains. With Hide Log Note as well, the chatter can only be read. Posting is refused on the server.
  • Hide Activities: the Activity button and the activities leave the chatter, lists, kanban cards and systray.
  • Both can be set everywhere (Restrictions tab) or for one data (under the menu).

8.4 The Settings app

Tick Hide the Settings App, or, on the Settings menu of the tree, untick only some of its apps (Sales, Inventory…). This matters for Settings users only, so tick Apply to Settings Users on the profile.

Part 9

Sign-in rules

9.1 Working hours and networks

The Sign-in tab sets when and from where the users of the profile may work. It is checked at sign-in and on every request: a session ends when the hours are over or when it is used from a network that is not allowed.

FieldMeaning
Working HoursA line per day, from and to, in the timezone you choose.
Allowed NetworksAddresses or ranges, e.g. 192.168.10.0/24.
One Session per UserSigning in ends the user's other sessions.
Block the External APIXML-RPC and JSON-RPC sign-ins refused; the browser still works.
Block Developer ModeThey cannot turn developer mode on.

Behind a proxy

If Odoo runs behind nginx or a load balancer, start it with --proxy-mode, or every request seems to come from the proxy's address.

9.2 Blocking a login

Block Login refuses every sign-in of the users of the profile, in the browser and through the API, and ends their open sessions at once. Their records are kept. Take a user out of the profile to let them back in, for example after a leave.

Part 10

Profiles for common roles

Each recipe starts from New from Template where one exists, then adjusts it. After each one, check the result with Preview as User (12.1).

10.1 Salesperson: own quotations, no delete

  1. New from Template › Salesperson, add the users.
  2. In the tree, click Sales › Orders › Quotations: Records = Their Own Records, untick Delete.
  3. Untick Sales › Configuration.
  4. Optional: under Buttons, set Cancel to Blocked; under Fields, make Discount read-only.

10.2 Accountant without configuration

  1. New from Template › Accountant without Configuration.
  2. To limit them to some journals, click the Invoicing / Accounting app and pick them under Allowed records (5.3).
  3. Optional: tick Block Export.

10.3 Read-only auditor

  1. New from Template › Auditor, or a new profile with Read Only Everywhere ticked.
  2. Options: Override, so no other profile of the user can give write access back.
  3. Optional: Hide Send Message and Hide Log Note.
  4. For a limited period, add the auditor under Temporary Users.

10.4 Warehouse operator on one warehouse

  1. New from Template › Warehouse Operator.
  2. Click Inventory, Allowed records: warehouses, tick Each User's Own.
  3. On each user's form, tab Allowed Records, set their warehouse.
  4. Optional: Hide Costs and Margins.

10.5 Purchase user without prices to edit

  1. New from Template › Purchase User.
  2. Click Purchase › Orders › Purchase: Fields, make Unit Price read-only; Buttons, block Confirm Order if a manager must confirm.

10.6 A replacement during a leave

Open the profile of the person on leave, tab Temporary Users, add the replacement with a start and end date. They get the profile on the first day and lose it after the last, on their own. To stop the absent person from signing in meanwhile, put them in a profile with Block Login and take them out when they are back.

Part 11

Point of Sale

11.1 The four POS modules

The Point of Sale is a screen of its own, so its rules come in separate, free modules (Odoo 18, 19 and 20, Community and Enterprise). Install only what you use:

11.2 What a cashier may not do

RuleIn the shop
No Refunds / Refunds Only From a ReceiptThe Refund button goes, or refunds only from the receipt of the sale: the +/- key cannot give money back. Refunds sent anyway are refused.
Maximum RefundRefunds up to an amount per order, taxes included.
No Discounts / Maximum DiscountNo discount, or a maximum per line: a higher one is brought down to it.

No Cancelling OrdersCancel Order goes; an order with products cannot be deleted.

The buttons leave the screen, and the server checks every order, cash move and closing the shop sends. A cashier with no rule keeps the shop as it is.

11.3 Rules on a user

With POS Access Control only: open the user, tab Point of Sale, and tick. It applies the next time they open the shop.

11.4 Rules on an access profile

With User Access Manager for POS, every profile gets a Point of Sale tab with the same rules: tick them once on a Cashiers profile and all its users get them. Changes are in the history and versions of the profile.

Combine it with the rest of the profile: Allowed records › points of sale with Each User's Own keeps each cashier on their own shop (5.3), and the Sign-in tab sets their hours (9.1).

11.5 Employees with a badge or a PIN

When cashiers log in at the till as POS employees:

  • POS Access Control for Employees adds a Point of Sale tab to the employee: switch on Own Point of Sale Rules and tick. Without it, the employee follows their Odoo user, or else the user who opened the shop.
  • User Access Manager for POS Employees adds POS Employees to the profile's Point of Sale tab: listed employees get the profile's rules at the till.

Switching cashier switches the rules, on the screen and on the server.

More on the Point of Sale

A separate guide for the POS modules, with every rule explained and what the cashier sees, ships in om_access_manager_pos, at static/description/user_guide.pdf.

11.6 How the rules combine

  • Rules on the profile and rules on the user (or employee) both apply: the strictest wins.
  • Between profiles: a restriction applies when every additive profile carries it, or any override profile does; a limit is the loosest of the additive profiles, tightened by the override ones.
  • Employees on no profile and without rules follow their Odoo user.

Part 12

Checking your work

12.1 Preview as User

Click Preview as User on a profile or on a user form, and pick a user. The window first lists their profiles and what they end up with; Open Preview then opens Odoo exactly as they see it: apps, menus, records, fields and buttons.

  • No password needed, and nothing is saved: the preview is read-only.
  • A banner at the bottom names the user; Exit preview brings you back. It covers every tab of your browser, for an hour at most.
  • Only access managers may preview, and only users with no more rights than their own.
  • Sign-in rules (hours, networks) are not simulated.

12.2 Why?

Access Manager › Why? answers can this user do this, and why not? Pick a user, a data, an operation and, if you like, a record. It shows Odoo's own access first, then each profile, its record filter, and the fields and buttons restricted. It also opens from the user form and from every refusal in the audit log.

12.3 Effective Access on the user form

The Access Profiles tab of a user lists their profiles; Effective Access shows what they really end up with, all profiles combined, and which profile produced each line.

12.4 Health Check

After a module is uninstalled or Odoo is upgraded, a rule can lose the menu, field or button it named. Access Manager › Health Check lists those rules, per profile, and runs on its own every week. For each line: Remove the dead rule, Open it, restore the last version, or accept the profile as it is. It never changes a profile by itself.

12.5 History, versions, export and import

  • History: every change of a profile is in its chatter, with who and when.
  • Versions: each save keeps a version. A version shows what changed, line by line, and Restore this Version brings it back; the users stay. The last 200 versions are kept.
  • Export / Import: select profiles and use Action › Export Profiles, then Import above the profiles list of the other database. Menus and reports are matched by external id, else by name; anything missing is listed in the profile's chatter.

Part 13

Upgrading Odoo, uninstalling

13.1 Moving to a new Odoo version

Keep the module installed: profiles, their users, versions and sign-in rules are ordinary records and move with the database. Then:

  1. Upgrade a copy of the database first.
  2. Run the Health Check on the copy, and set again what it lists.
  3. Check the main profiles with Preview as User.
  4. Go live.

Exporting the profiles before the upgrade, and importing what is missing after it, is a second safety net. The module exists for every version from 15 to 20, so you can stay on it all the way.

13.2 Uninstalling

Uninstalling removes the access profiles and every group a profile granted: users keep only the groups of their own form, and every restriction ends. The User Audit & Sessions app stays installed, with its log.

14.2 The usual questions

A restriction does nothingThe user has another additive profile that allows it. Copy the restriction into that profile too, or use an Override profile. Why? shows which profile allows it.
An administrator is not restrictedDeliberate: the Administrator is never restricted, and Settings users only with Apply to Settings Users.
A user's screens break with an errorRead was denied on data the interface needs. Remove the profile from the user, then give back Read on that data.
The hidden value still shows on a PDF or an emailOdoo builds documents with its own rights: hide that report too.
Allowed networks refuse everyoneOdoo is behind a proxy: start it with --proxy-mode.
The menus do not follow the company switcherA profile follows the user's companies, not the company being worked in.
After an upgrade, rules are missingRun the Health Check (12.4) and restore or set them again.
A change is refused: "last access manager"Someone must keep the right to open the Access Manager. Give it to another user first.

14.3 Getting help

Write to odoomates@gmail.com with your Odoo version, the module version (Apps › the module › Module Info) and, when you can, a screenshot of Why? for the user and the operation. Feedback and wishes are welcome: they make the app better.

The app is translated into Arabic, German, Spanish, French, Italian, Dutch, Brazilian Portuguese, Russian, Turkish and Simplified Chinese. Missing your language, or a better word? Write to us.
