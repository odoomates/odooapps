What it controls

Everything a user sees and does, profile by profile

Group users into access profiles. A user may carry several: they combine like Odoo groups, and an override profile always wins, for a blanket such as "Read Only" stacked on top. A user with no profile is not restricted at all.

An app of its own

Access Manager, on the home screen of the Access Management group: the Administrator from the start, and whoever you add. No Settings rights needed to manage the profiles.

Grant an app

Tick an app in the menu tree to open it to users whose form leaves it out (Purchase / User), then restrict it like any other. Taken away with the profile; never an administrator group.

Who gets a profile

Pick the users, or an Odoo group whose members all carry it, or give it for a while: from one date to another, for a replacement during a leave. Copy or move a user's access to another in one click.

The menu tree

Everything is set on the real menus of your database: untick a menu to hide it, click it to set what its users may do there. Set an app or a submenu, and everything below follows, apps installed later included.

Data and records

Read, create, edit and delete, and which records: their own, their team in the org chart, their sales team, their companies, their warehouse, created this month, drafts only, or any filter built with Odoo's filter editor.

Allowed records

Only these journals, points of sale, warehouses, locations, sales teams or dashboards, and only what belongs to them. Per profile, or per user: one Cashier profile, each cashier on their own shop.

Fields

Hide a field, make it read only or required, for every record or only those matching a condition such as confirmed orders, with one switch for all the costs and margins and one for the sales prices. Hidden values never leave the server.

Buttons, reports and actions

Hide or block any button, always or once the record matches a condition (Cancel refused on confirmed orders), any report and any entry of the Action menu, or the whole Print or Action menu of a model.

The screen

Hide the chatter or only Send message, the followers, the attachments, the activities, tabs, filters, view types; lock status bars; block export (or one field of it), import, archiving and duplication; no custom filters, saved searches or new properties.

Sign-in

Working hours in the timezone you choose, allowed networks, one session per user, blocked login, blocked external API and developer mode.

Preview, safety and history

Preview as User, read only; effective access on the user form, saying which profile and which menu each right comes from; a change history on every profile, export and import between databases, refusals in the audit log, and the last access manager is never locked out.

Tick an app to give it

Open an app their user form leaves out, with one tick

An app the users of the profile cannot open shows unticked, marked Not given. Tick it: they get its user level (Purchase / User), and the profile restricts it like any other app. Untick it and it is taken back. Remove a user from the profile and the app goes with it.

✓  Only the groups of the app are given; groups that would make users administrators or access managers never are.

How to use it

Your first profile in a few minutes

1.Open the Access Manager app, and click New from Template, or create an empty profile.
2.Add the users, an Odoo group, or users for a while; or select them in the Users list and use Action > Set Access Profiles.
3.On the Menus & Apps tab, untick the apps and menus they must not see, and click an app to pick a level (read only, no configuration...). An app marked Not given: tick it to give it to them.
4.Click the menus that differ, and set their rights, records, fields and buttons beside the tree.
5.Check the result with Preview as User: Odoo as they will see it, read only.
Good to know

What it does, and what it does not

Access profiles take access away, and can open an app a user form leaves out; nothing else is ever given.

✓  Administrators are not restricted unless a profile says so, and the Administrator user never is.
✓  Odoo's own code keeps working: hiding the cost does not stop a delivery from being validated.
✓  A document Odoo prints itself (a quotation PDF, an email) can still show a hidden value: hide that report too.
✓  Behind a reverse proxy, start Odoo with --proxy-mode so that the allowed networks see the real addresses.
✓  Odoo checks rights per data, not per menu: what you set on Quotations applies to Orders too, since both open sales orders. The panel says so.
✓  It depends on the standard Mail and RPC modules and on our free User Audit & Sessions app, installed with it: it works with any set of apps.

Questions we get

Is a hidden field really hidden?
Yes. It leaves the screens, and the server blanks its value in everything a user, the browser console or a script reads, and refuses to filter, group or export on it.

Can Quotations and Orders have different rights?
Not on the server: both open the same data, and Odoo checks rights per data. Hide one of the two menus, or use a condition on a field or a button (only on confirmed orders, for instance).

Can a user carry several profiles?
Yes. Additive profiles combine permissively, like Odoo groups; an override profile always applies. Preview as User shows the result.

Can I move my profiles to production?
Yes: export them from the test database and import them on production. What production lacks is listed on the profile.

It is a beta: can I use it?
Yes, with the usual care: try your profiles on a copy of your database first. Your reviews, bug reports and ideas are welcome: they decide what comes in the first stable release.

Who manages the profiles?
The members of the Access Management group, in the Access Manager app: the Administrator from the start, and anyone you add on their user form. They need no Settings rights.

What happens when I uninstall it?
Every restriction disappears with it, and so does the access the profiles granted. The groups set on the user forms are never touched.
