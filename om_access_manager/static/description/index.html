What it controls

Everything a user sees and does, profile by profile

Group users into access profiles. A user may carry several: they combine like Odoo groups, and an override profile always wins, for a blanket such as "Read Only" stacked on top. A user with no profile is not restricted at all.

Apps and menus

Hide whole apps or single menus on the real menu tree, with a search, and the Settings app.

Data and records

Read, create, edit and delete per kind of data, and which records: their own, their sales team, their companies, their warehouse, drafts only, or any filter built with Odoo's filter editor.

Allowed records

Only these journals, points of sale, warehouses, locations, sales teams or dashboards, and only what belongs to them. Per profile, or per user: one Cashier profile, each cashier on their own shop.

Fields

Hide a field, make it read only or required, with one switch for all the costs and margins and one for the sales prices. Hidden values never leave the server.

Buttons, reports and actions

Hide or block any button, any report and any entry of the Action menu, or the whole Print or Action menu of a model.

The screen

Hide the chatter or only Send message, the followers, the attachments, the activities, tabs, filters, view types; lock status bars; block export, import, archiving and duplication.

Sign-in

Working hours in the timezone you choose, allowed networks, one session per user, blocked login, blocked external API and developer mode.

Safety and history

Effective access on the user form, a change history on every profile, export and import between databases, and the Administrator is never locked out.
Restrict an App

An app in one screen

Pick an app: its menus, its data, its reports and its actions are listed with a checkbox each. An access level (full, user without configuration, read only, no access) ticks them for you. Data the app shares with other apps, such as customers, is marked and never changed by a level.

Every kind of data has its rights and its filter. The buttons write the usual filters for you, offered only when the data has what they need; Odoo's filter editor does the rest.

Pick them by name. Everything that belongs to them follows: allowing two journals also filters their entries, journal items and payments. Tick Each User's Own to read them from each user's form instead.

How to use it

Your first profile in a few minutes

1.Go to Settings > Users & Companies > Access Profiles, and click New from Template, or create an empty profile.
2.Click Restrict an App for each app the profile must limit, and pick a level.
3.Fine-tune the tabs if needed: the menu tree, the records, the fields, the sign-in rules.
4.Add the users, or select them in the Users list and use Action > Set Access Profiles.
5.Check the result with Test as User, then sign in as one of them.
Good to know

What it does, and what it does not

Access profiles only take access away: a user never gets more than their Odoo groups allow.

✓  Administrators are not restricted unless a profile says so, and the Administrator user never is.
✓  Odoo's own code keeps working: hiding the cost does not stop a delivery from being validated.
✓  A document Odoo prints itself (a quotation PDF, an email) can still show a hidden value: hide that report too.
✓  Behind a reverse proxy, start Odoo with --proxy-mode so that the allowed networks see the real addresses.
✓  It depends on nothing but the standard Mail and RPC modules: it works with any set of apps.

Questions we get

Is a hidden field really hidden?
Yes. It leaves the screens, and the server blanks its value in everything a user, the browser console or a script reads, and refuses to filter, group or export on it.

Can a user carry several profiles?
Yes. Additive profiles combine permissively, like Odoo groups; an override profile always applies. Test as User shows the result.

Can I move my profiles to production?
Yes: export them from the test database and import them on production. What production lacks is listed on the profile.

It is a beta: can I use it?
Yes, with the usual care: try your profiles on a copy of your database first. Reviews, bug reports and ideas are welcome; they decide what comes in the first stable release.

What happens when I uninstall it?
Every restriction disappears with it: the module only subtracts access, it never changed your groups.
