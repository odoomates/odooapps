What it records

Every sign-in, every change, every export

From the installation on, every operation of every user on your business data is logged, without any setting. Odoo's own work in the background is not: only what the users and their scripts do.

Sign-ins

Every sign-in, failed sign-in and sign-out, with the address and the browser. A failed sign-in is kept even though Odoo cancels everything else of the request. Sign-ins through the API are marked.

Changes

Every record created, edited or deleted, with the old and the new value of each field that changed: Phone: 111 → 222. A price, a salesperson, a status.

Reads

One line per screen opened or call made by a script (XML-RPC, JSON-RPC, JSON-2), with the number of records and their first ids.

Exports, imports, prints

The fields exported and how many records, the rows imported, the report printed and on which record.

Sessions

Every signed-in browser and device, with its address, country and city, first and last activity. End one session, or all those of a user.

Idle sessions and emails

Sign out a user idle for too long. An email on every sign-in, to the user, to the administrators or both, optionally only from a new device.

Rules

Log everything, or only what matters: some data, some operations, some users or groups.

Clean-up

The logs are deleted after the number of days you choose, the sign-ins after another, every night.

Reports

A list, a pivot and a graph of the logs, the activity and sessions of a user on their form, and a PDF of a period for the auditors.

Settings

Retention, sign-in emails, idle sessions

How long the logs and the sign-ins are kept, whether reads are logged, what is never logged, who gets an email on each sign-in, and after how long an idle session ends.

The number of lines written in the last 24 hours tells how fast the log grows.

Rules

Log everything, or only what matters

With no rule, everything is logged but the technical data. As soon as a rule exists, only what the rules name is: the sales and invoices, the changes and exports of the contacts, everything one accountant does.

How to use it

Logging in one click

1.Install the app: everything is logged from now on.
2.Open User Audit > Logs to see what happens today, and User Audit > Sessions for who is signed in.
3.In User Audit > Configuration > Settings, choose how long the logs are kept, the sign-in emails and the idle sessions.
4.If the log grows too fast, turn the reads off, or add rules in What to Log to keep only what matters.
Good to know

What it does, and what it does not

The log is readable by the Settings users only.

✓  Odoo's own code running as the superuser is not logged: it would only log Odoo's bookkeeping. Changes a user makes, even through a button, are.
✓  Reads are the most frequent event: on a busy database, turn them off in Settings or name only the data that matters.
✓  Behind a reverse proxy, start Odoo with --proxy-mode so that the log shows the real addresses.
✓  With our User Access Manager, every refusal of an access profile and every session it ends land in this log too.
✓  It depends on nothing but the standard Mail and RPC modules: it works with any set of apps.

Questions we get

Does it slow Odoo down?
Barely: the lines of a request are written once, when it ends, in one go. Reads can be turned off everywhere at once if you do not need them.

Does a cancelled change leave a line?
No: a change rolled back leaves nothing. A failed sign-in or a refusal is kept, written on its own.

Can users see the log?
No, only the Settings users. Each user still sees their own sessions in their preferences, as in standard Odoo.

How do I keep the log small?
Choose how long it is kept in Settings, turn the reads off, or add rules: only what they name is logged.

It is a beta: can I use it?
Yes, with the usual care: try it on a copy of your database first. Reviews, bug reports and ideas are welcome.
