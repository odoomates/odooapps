Nothing goes through us
The requests go from your Odoo server straight to the provider you choose, with your key. Keys stay on the server and are never sent to the browser. With a local model server, no data leaves your network.
Providers

Use the AI you want

One adapter for every OpenAI compatible API, native adapters for the others, and local servers without a key.

OpenAI compatible
OpenAI, Mistral, Groq, DeepSeek, xAI, OpenRouter, Together, Perplexity or any compatible endpoint.
Native adapters
Anthropic Messages API (Claude), Google Gemini API and Azure OpenAI.
Local models
Ollama, LM Studio, vLLM and LocalAI with their local addresses filled in, no key needed.
Test and fetch
Test Connection in one click, and Fetch Models adds the models of the provider.

Providers and models

Pick the provider type and the base URL is filled in. Type the key once: it is saved on the server and never shown again. Fetch the models, then set their capabilities (chat, vision, tools, JSON output, embeddings) and their prices per million tokens for cost estimates.

Defaults and limits per company

Set a default model for chat, fast answers, vision and embeddings: features ask for a purpose, not a model. Daily limits per user and per company, in tokens or cost, stop calls once they are reached. Logging the text sent to the AI is off unless you turn it on.
Features

Ready to use

Two features come with the engine; more Odoo Mates apps build on it.

AI Assistant in Discuss

Every AI user gets a chat with the AI Assistant. Ask "How many customers do we have in Belgium?": it looks the answer up with read-only tools that run with your access rights, so it only sees the records you may see. Answers come in the background with a typing indicator, and a reached limit is told in the chat.

Write with AI in the editor

Type / in any text editor and choose Write with AI: describe the text, refine it, insert it. With the setting on, the editor text generation of Odoo (and the website texts that use it) goes to your own provider instead of Odoo's service.
Control

Know what it costs

Every call is logged with its tokens, estimated cost and duration.

Usage log

By user, feature, provider and model, in a graph, a pivot or a list. Users see their own usage; AI administrators see everyone's. Errors and calls blocked by a limit are logged too, and old logs are removed after the number of days you choose.
For developers

One engine for all your AI features

A small Python API with the same format for every provider.

Chat API
_ai_chat(messages, purpose, tools, json_schema, images, stream): text, tool calls, JSON and usage in one format.
Tools and agent loop
A registry of tools and an agent loop that runs them as the user. Tools that change data wait for the user to confirm.
Retries and errors
Busy and failing providers are retried with a growing pause; errors show the provider's message.
Prompt templates
Reusable prompts with {{ placeholders }}, filled in as plain text, never evaluated.

Tools the AI may call

Find models, list fields, search, read, count and aggregate records, read attachments. Create, update and delete records, post in the chatter and attach files, always as the user. Turn a server action into a tool, limit a tool to some models or groups, or add your own tool with a record and a method.
Good to know
  • You need an account and a key with the provider you choose, or a local model server. Provider costs are billed by the provider.
  • The adapters follow the public API documentation of each provider. Check the connection with your own key before you rely on it.
  • Costs are estimates from the prices you enter.
