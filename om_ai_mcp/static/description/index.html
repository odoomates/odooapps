Never more than the user may do
Every tool runs as the user who signed in or owns the key, never as superuser: access rights, record rules and companies apply. On top of that you choose which models MCP clients may use and what they may do on each of them.
Connect

Your AI app, your Odoo

One endpoint on your Odoo server. Browser apps sign in with OAuth, the others use a key per user. Ready-to-paste settings for the usual MCP clients.

Browser apps
Apps with custom connectors only need the URL: the user signs in to Odoo and allows the app.
Desktop apps
Claude Desktop through the mcp-remote bridge, with your key in an environment variable.
Code editors
Cursor and VS Code with the native HTTP transport; VS Code asks for the key once.
Command line
Claude Code in one command, and the MCP Inspector to list and try the tools.
OAuth 2.1

Sign in with Odoo, no key to copy

Odoo is its own authorization server for MCP: discovery from the 401, dynamic registration, PKCE, resource indicators, refresh token rotation and revocation, without any outside service.

The user decides

The app sends the user to Odoo. After the usual login, a consent page shows the app, where the answer goes and a Create and modify data switch. Off, which is the default, the app gets a read-only token: tools that change data are hidden and refused.

Connected apps

Users see the apps they connected, what each may do and when it was last used, and disconnect them in one click. Administrators see the apps of every user. Tokens expire, refresh tokens rotate, and only hashes are stored.

Apps under control

Apps register themselves, or you add them yourself. Turn on approval and new apps wait for an administrator; block an app and its connections end at once. Token and connection lifetimes are settings.
Resources and prompts

More than tools

AI apps also read Odoo resources and use your prompt templates, with the same permissions.

Records, reports and files as resources

odoo://record/{model}/{id} gives the fields of a record, odoo://report/{report}/{ids} the printed PDF, odoo://attachment/{id} a file. Plus the current user, the models open to MCP and their fields. Only models in the model permissions, with the user's rights and record rules.

Your prompt templates in the AI app

Check Available to MCP on a prompt template of the AI Engine: AI apps list it (often as a slash command) and ask for its placeholders. Two demo prompts are included.
Keys

For apps without OAuth

An MCP key per user, read-only keys, and the settings for each app.

A Connect page for every user

AI > MCP Server > Connect shows the endpoint URL, creates an MCP key or a read-only key (after the password check), and gives the settings for each app with your server address filled in.

Copy, paste, done

The JSON for Cursor and VS Code, the command for Claude Code and the Inspector. When the server hosts several databases, the database header is added for you.

Keys that only open the MCP door

MCP keys are Odoo API keys with their own scope: they work on the MCP endpoint only, not on the other APIs, and follow the usual expiry rules. A read-only key only sees the tools that do not change data.
Tools

One tool registry for every AI feature

The MCP server offers the tools of the AI Engine, the same ones the AI Assistant in Discuss uses. Each comes with its JSON schema and MCP annotations.

Read
Find models, list fields, search, read and count records, current user and companies.
Aggregate
Sum, average, min, max and count, grouped by up to three fields, dates by month or year.
Change
Create (lines included), update and delete records, a set number per call. Post in the chatter.
Files and actions
List, read and attach files (images come back as pictures). Server actions as tools.

Try it from a terminal

The answers are JSON text and structured content, images for image attachments. Tool errors (access refused, wrong values) come back as tool results the AI can correct; tracebacks are never sent.

Choose the tools

Every tool of the registry can be hidden from MCP clients. Turn a server action into a tool with a name, a description and a parameters schema: the AI gets it at once.
Control

You decide, and you can check

Model permissions, an opt-in group, rate limits and a log of every request.

Model permissions

List the models AI apps may use, each with Read, Create, Write (also chatter and files), Delete and Server Actions. Models that are not listed are not available, and tools that no permission allows are not offered.

Audit log

Every request with its user, key, client, tool, model, duration, status and error. Written in its own transaction, so failed calls are kept too. Old logs are removed after the number of days you choose.

Settings

Turn the server and the OAuth sign-in on or off, allow app registration (with or without approval), set token lifetimes, the rate limit (requests per key in a sliding window), the records per call, the log retention, the browser origins allowed to call the endpoint and extra instructions for the AI.
Good to know
  • Needs the free AI Engine (om_ai) of Odoo Mates. No AI provider key is needed for MCP: the AI runs in your app.
  • Only users in the MCP User group can create MCP keys and connect.
  • Browser apps sign in with OAuth 2.1; other apps use an MCP key in an Authorization header.
  • Your Odoo must be reachable from the AI app, over HTTPS for OAuth.
  • The server answers requests only, so it does not announce list changes: AI apps list the tools, resources and prompts again when needed.
